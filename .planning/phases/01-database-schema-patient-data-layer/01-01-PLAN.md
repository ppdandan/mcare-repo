# Plan 01-01: Prisma Schema & Database Initialization

## Objective
Establish the foundational Next.js TypeScript backend architecture with Prisma ORM and SQLite, defining both the Phase 1 clinic models (staff, appointments, payments, medical records, clinic settings) and the Phase 2 patient mobile extensions (patient credentials, app linkage, and notification tables).

## Proposed Changes

### Monorepo Backend Foundation
- Configure root `package.json` with Next.js 16, TypeScript, Prisma, `@prisma/client`, and `bcryptjs`.
- Configure `tsconfig.json` with path aliases (`@/*`).
- Create `src/lib/prisma.ts` with singleton pattern for `PrismaClient` to prevent connection leaks during development.

### Prisma Schema Definition (`prisma/schema.prisma`)
- Define datasource SQLite (`file:./dev.db`).
- Models:
  - `User`: Staff accounts (ADMIN, DOCTOR, RECEPTIONIST) with username, passwordHash, role, name.
  - `ClinicSettings`: Clinic operating hours, operating days, appointment interval in minutes (default 30m), address, contact.
  - `Patient`: Core patient entity with `patientId` (MC-XXXX), firstName, lastName, middleName, contactNumber, address, birthDate, emergencyContact, `isAppUser` (Boolean), `passwordHash` (String, optional for staff-only patients), `verificationStatus` (PENDING, VERIFIED), `appRegisteredAt` (DateTime, optional).
  - `Appointment`: `appointmentId` (AP-XXXX), patientId, doctorId, appointmentDate, timeSlot, appointmentType (CHECKUP, ULTRASOUND), status (PENDING, APPROVED, COMPLETED, REJECTED, CANCELLED), notes.
  - `Payment`: `paymentId`, appointmentId, patientId, totalAmount, amountPaid, balance, status (PENDING, PARTIAL, PAID, REFUNDED).
  - `MedicalRecord`: `recordId`, patientId, doctorId, diagnosis, prescription, clinicalNotes (staff-only).
  - `Notification`: `notificationId`, patientId, title, message, type (STATUS_UPDATE, REMINDER, GENERAL), isRead, createdAt.

### Database Seeding (`prisma/seed.ts`)
- Seed clinic settings for M-Care OB-GYNE Clinic & Ultrasound (Balibago, Angeles City).
- Seed default staff accounts (admin, doctor, receptionist).
- Seed sample existing patients (e.g. `MC-0001` Maria Santos, `MC-0002` Ana Reyes) to enable returning-patient matching tests.
