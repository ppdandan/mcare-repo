# Plan 01-02: Patient Data Access & Returning Matching Service

## Objective
Implement and verify the patient data access layer, including phone number normalization, returning-patient matching algorithm (matching by name and contact number against existing Phase 1 records), account linkage logic, and patient profile retrieval.

## Proposed Changes

### Phone & Name Normalization (`src/utils/phone.ts`)
- Implement `normalizePhoneNumber(raw: string): string` to convert Philippine mobile numbers across all common representations (`+639XXXXXXXXX`, `09XXXXXXXXX`, `9XXXXXXXXX`, formatted with spaces/dashes) into a canonical 11-digit format (`09XXXXXXXXX`).
- Implement `normalizeName(name: string): string` to trim whitespace and lowercase strings for case-insensitive matching.

### Returning-Patient Matching Service (`src/services/patientMatching.ts`)
- Implement `findReturningPatient(params: { firstName: string, lastName: string, contactNumber: string })`:
  - Query database for existing `Patient` with matching normalized contact number and case-insensitive first and last name.
  - Return `{ matchFound: true, patient: existingPatient }` if matched.
  - If phone matches but name differs, or name matches but phone differs, return `{ matchFound: false, reason: 'MISMATCH_FLAGGED', candidateId: ... }` to avoid false auto-links while notifying staff.
  - If no record matches, return `{ matchFound: false }`.
- Implement `linkPatientAccount(params: { patientId: string, passwordHash: string })`:
  - Update the existing `Patient` record setting `isAppUser: true`, `passwordHash`, `verificationStatus: VERIFIED`, `appRegisteredAt: new Date()`.
  - Guarantees the existing `MC-XXXX` ID is preserved and no duplicate patient record is generated.

### Patient Profile Service (`src/services/patientProfile.ts`)
- Implement `getPatientProfile(patientId: string)`:
  - Retrieve patient details: `patientId` (MC-XXXX), `firstName`, `lastName`, `middleName`, `contactNumber`, `address`, `birthDate`, `emergencyContact`, and `verificationStatus`.
  - Exclude sensitive fields like `passwordHash`.

### Automated Testing (`tests/patientMatching.test.ts`)
- Unit test suite verifying:
  - Phone normalization with various inputs (`+639171234567`, `0917-123-4567`, `917 123 4567`).
  - Returning patient auto-matching succeeds against seeded patient `MC-0001` (Maria Santos).
  - Linking account updates `MC-0001` without altering the ID.
  - New unregistered patient returns `matchFound: false`.
  - Querying profile returns clean profile object with `patientId`.
